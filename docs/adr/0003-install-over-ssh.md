# Нода ставится по SSH, а не init-скриптом

API Serverspace принимает `server_init_script`, но не выполняет его. 2026-10-29 это проверили так: создали сервер со скриптом из двух строк, `sleep 10` и `poweroff`. И на Ubuntu 26.04, и на 24.04 сервер за 5 минут так и не выключился. До этой проверки ни один реальный запуск minivpn не дошёл до установки, хотя на тестовом стенде всё работало. Зато API отдаёт root-логин и пароль нового сервера. Поэтому приложение заходит по SSH, запускает тот же скрипт отдельно от сессии и построчно читает его лог. Скрипт в конце выключает SSH.

## Considered Options

- **Init-скрипт с отчётом тегами сервера и маяком на порту 80.** Отклонено: хостер не запускает скрипт, отчитываться нечему.
- **Другой хостер с рабочим cloud-init.** Отложено: пришлось бы заново выбирать цену, локацию и API, а SSH решает задачу у этого хостера.

## Consequences

- Ключ хоста нового сервера ничем не подтвердить: API его не сообщает. Первое подключение принимается на доверии, отпечаток пишется в лог. Для ноды, которая живёт одну сессию, это допустимо.
- Пароль приложение берёт из API на каждый запуск и нигде не хранит. Пока сервер грузится, хостер принимает пароль не сразу, а примерно через 40 секунд после создания, и установщик повторяет попытки.
- Каждая строка установки видна в логе и в панели, поэтому сбой называет шаг и причину.
- От создания до готовой ноды проходит ~50 секунд, сама установка занимает ~10 секунд.
